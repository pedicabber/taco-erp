# PRD #23 – Timeclock Edit Capability & Automatic End-of-Day Clock-Out

## Priority

High Priority

---

# Problem Statement

The ERP currently allows employees to clock in and clock out, but there is no controlled mechanism for correcting mistakes when timestamps are entered incorrectly or when an employee forgets to clock out.

This creates two issues:

1. Employees cannot correct legitimate clock-in or clock-out mistakes.
2. Open timeclock entries can continue running indefinitely if an employee forgets to clock out, creating inaccurate labor records and reporting.

---

# Objective

Provide a controlled time-editing workflow for employees while ensuring accurate payroll and labor tracking through automatic end-of-day clock-out protection.

---

# Done Looks Like

* Employees can edit their own clock-in and clock-out timestamps.
* All timestamp edits are permanently recorded in an audit history.
* Managers/Admins can see original values and modified values.
* Active timeclock entries automatically clock out at 9:00 PM PST if still running.
* Auto-clocked entries are clearly identified.
* Labor reporting reflects corrected times.
* No time entry can remain running indefinitely.

---

# Employee Timestamp Editing

Employees may edit:

* Clock In Time
* Clock Out Time

For their own entries only.

Employees may not edit:

* Other employee time records
* Audit history
* Auto-generated system audit records

---

# Edit Time Entry Workflow

### Time Entry Details

Display:

* Original Clock In
* Original Clock Out
* Current Clock In
* Current Clock Out

Button:

```text
Edit Time Entry
```

---

### Edit Form

Fields:

* Clock In Date/Time
* Clock Out Date/Time
* Edit Reason (required)

Examples:

* Forgot to clock in
* Forgot to clock out
* Mobile issue
* Incorrect timestamp
* Other

---

### Save Action

Upon save:

* Record new values
* Preserve original values
* Create audit entry

---

# Time Edit Audit Trail

Every edit shall create a permanent record:

Display:

```text
Original Clock In:
6:55 AM

Updated Clock In:
7:00 AM

Edited By:
John Smith

Date:
06/05/26

Reason:
Forgot to clock in
```

Audit records shall never be deleted.

---

# Auto Clock-Out Protection

If a timeclock entry remains active at:

```text
9:00 PM PST
```

the system shall automatically:

* Clock the employee out
* End the active timer
* Record an audit event

---

# Auto Clock-Out Audit Record

Example:

```text
Clock Out:
9:00 PM PST

Status:
System Auto Clock-Out

Reason:
Automatic end-of-day protection
```

---

# Auto Clock-Out Rules

Only applies to:

* Active/running time entries

Does not apply to:

* Already clocked-out entries
* Historical entries

---

# User Visibility

Time entries that were auto-clocked shall display:

```text
AUTO CLOCKED OUT
```

or similar visual indicator.

Users should be able to easily identify system-generated clock-outs.

---

# Administrative Visibility

Admins shall be able to view:

* Original timestamps
* Modified timestamps
* Edit reason
* Auto clock-out events

---

# Notifications

Optional but recommended:

At 8:45 PM PST:

Send notification to users with active time entries:

```text
You are currently clocked in.
Your time entry will automatically clock out at 9:00 PM PST if not manually closed.
```

---

# Reporting Requirements

Reports shall:

* Use the final approved timestamps
* Preserve audit history
* Identify auto-clocked records

---

# Security Requirements

Employees may only edit their own time entries.

Admins may edit any time entry.

All edits must be logged.

No audit history may be deleted.

---

# Acceptance Criteria

### Employee Edit

* Employee edits their own time entry.
* Reason is required.
* Audit history is created.

### Auto Clock-Out

* Active entry reaches 9:00 PM PST.
* System automatically clocks out the user.
* Audit event is created.
* Entry is marked as auto-clocked.

### Security

* Employee cannot edit another employee's time entry.
* Admin can edit any entry.

### Reporting

* Reports use corrected timestamps.
* Audit history remains available.

---

# Architectural Notes

* Store original timestamps and edited timestamps separately.
* Auto clock-out events should be generated by a scheduled server-side job, not browser/client logic.
* Use America/Los_Angeles timezone for the 9:00 PM PST/PDT cutoff.
* All audit records must remain immutable.
